# Архитектура

DualAudio — локальное приложение C# / WinForms для Windows 11 x64, собранное под `net10.0-windows`. Для доступа к аудиоустройствам используется NAudio 2.2.1 и Windows WASAPI. Главный проект находится в `src/DualAudio/DualAudio.csproj`.

## Маршрут звука

Источник — выбранное устройство **воспроизведения**, с которого WASAPI loopback получает системный микс. Микрофон для этого не используется. Обычный маршрут:

```text
Приложения Windows → Bluetooth-выход → Bluetooth-наушники
                              │
                         WASAPI loopback
                              │
                  стереодекодер → очередь → проводной выход
```

`AudioRouter` создаёт один сеанс захвата и до двух программных выходов. Если выбранный выход совпадает с источником, отдельный поток для него не создаётся: устройство уже воспроизводит исходный звук. Это предотвращает повторный захват собственной копии и нарастающую обратную связь.

Отдельный виртуальный источник тоже допустим. В таком случае обе реальные пары получают независимые копии. Виртуальный драйвер устанавливается и настраивается отдельно от DualAudio.

## Захват и форматы

`SafeLoopbackCapture` использует WASAPI loopback в shared mode с запрашиваемым буфером 20 мс и защищённой обработкой ошибок остановки. На источнике работает дополнительный поток `ZeroProvider`, выдающий только нули. Он поддерживает непрерывную аудиовременную шкалу во время пауз: короткое уведомление получает последующую тишину и не застревает в ещё заполняющемся буфере задержки. Захваченный звук в этот поток не возвращается.

`StereoDecoder` преобразует микс источника в стерео float32 с частотой источника. Поддерживаются PCM 8/16/24/32 бит и float32/float64. Моно копируется в оба канала; многоканальный звук сводится в стерео с учётом маски каналов, без добавления LFE. Некорректные нечисловые значения заменяются нулями.

Каждый программный выход использует отдельный `WasapiOut` в shared mode с событиями и запрашиваемым буфером 80 мс. Преобразование частоты к формату устройства выполняет WASAPI. Запрашиваемые размеры буферов не являются измеренной полной задержкой: фактическое поведение зависит от аудиодвижка и драйвера.

## Независимые очереди

На каждый программный выход создаётся `AdaptiveAudioBuffer` с собственной позицией чтения. Остановка или переполнение одного потребителя не сдвигает очередь другого.

- Кольцевая очередь ограничена по размеру; стандартная ёмкость — 3000 мс.
- Начальное заполнение оставляет резерв 40 мс сверх заданной задержки и текущего запроса чтения.
- Пустое чтение возвращает свежие нули и не обозначает конец потока.
- Переполнение удаляет старые полные стереокадры, сохраняя новые.
- После длительного накопления очередь сокращается, чтобы не проигрывать многосекундный старый фрагмент.
- При прерывании захвата во время начального заполнения устаревшие данные удаляются.

Небольшая адаптивная коррекция скорости чтения с линейной интерполяцией удерживает очередь при расхождении частот независимых устройств. Предел коррекции — ±2000 ppm, то есть ±0,2%. Это компенсация дрейфа, а не автоматическое измерение акустической задержки Bluetooth.

Увеличение задержки вставляет тишину, уменьшение пропускает соответствующее число кадров. После разрыва применяется короткое нарастание громкости. Движок допускает задержку до 2000 мс; пользовательский интерфейс ограничивает её диапазоном 0–1500 мс.

## Жизненный цикл и выбор выхода Windows

Перед сменой системного выхода приложение открывает аудиопотоки. Если инициализация не удалась, автоматическое переключение не выполняется. Фатальная ошибка аудиосеанса останавливает передачу; повторный запуск остаётся действием пользователя.

Опциональный `DefaultOutputLease` сохраняет исходные устройства ролей Console и Multimedia, затем назначает выбранный источник. Communications не меняется. При остановке каждая изменённая роль восстанавливается только если она всё ещё указывает на источник приложения; ручной выбор пользователя не перезаписывается. Частично успешное назначение вызывает попытку отката. Недоступность прежнего устройства может помешать восстановлению.

Назначение выполняется через внутренний, недокументированный COM-интерфейс `IPolicyConfig`. Его доступность не гарантируется будущими версиями Windows; ручной выбор в параметрах звука остаётся рабочим вариантом. Восстановление выполняется при штатной остановке и закрытии, но не гарантируется после принудительного завершения процесса, сбоя системы или отключения питания.

## Состояние и границы

`AppSettings` сохраняет идентификаторы устройств, задержки, громкость и настройку переключения в `%LOCALAPPDATA%\DualAudio\settings.json` через временный файл. Трей скрывает окно, сохраняя сеанс; обычное закрытие завершает передачу. Именованный mutex предотвращает второй обычный экземпляр в той же пользовательской сессии.

Сетевых сервисов и собственного драйвера у приложения нет. Звук обрабатывается в памяти. Диагностические команды отдельно создают запрошенные текстовые отчёты или снимок интерфейса.

Пределы механизма loopback описаны в [документации Microsoft](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording). Исходный код используемой аудиобиблиотеки: [NAudio 2.2.1](https://github.com/naudio/NAudio/tree/v2.2.1).
