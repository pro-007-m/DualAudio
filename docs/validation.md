# Проверки

Проверки разделены на детерминированные проверки движка, создание интерфейса и ручную проверку реального оборудования. Успешная сборка или наличие сигнала на loopback не заменяют прослушивание обеих пар и оценку их акустической задержки.

## Проверка текущих исходников

При подготовке публичного выпуска 2026-11-03 локально прошли сборка Release без
предупреждений и ошибок, все десять проверок движка, извлечение лицензионных
уведомлений, создание и проверка интерфейса, публикация одного автономного EXE
и повторная самопроверка опубликованного файла. В этой подготовке аппаратное
прослушивание не повторялось. Результаты GitHub Actions доступны в репозитории.

Из корня репозитория на Windows с .NET SDK 10:

```powershell
.\scripts\build.ps1
.\scripts\test.ps1
.\scripts\publish.ps1
```

Отчёты и готовые файлы создаются в `artifacts/`. Результат каждой такой проверки относится к конкретной собранной версии. Исторические результаты ниже не означают повторную аппаратную проверку каждого последующего коммита.

Команда самопроверки движка также доступна напрямую:

```powershell
dotnet run --project .\src\DualAudio\DualAudio.csproj -c Release -- --self-test .\artifacts\self-test.txt
```

Десять проверок `EngineTests` не открывают аудиоустройства, не воспроизводят сигнал и не меняют выход Windows:

| Проверка | Проверяемое поведение |
| --- | --- |
| Пустой буфер | Свежие нули вместо повторения старых сэмплов; соблюдение границ выходного массива |
| Переполнение | Ограниченная очередь сохраняет новые полные стереокадры |
| Переход конца кольца | Порядок кадров и каналов сохраняется |
| Короткое уведомление | Звук короче заданной задержки воспроизводится с последующей тишиной |
| Прерванный запуск | Старое уведомление не возвращается после разрыва захвата |
| Изменение задержки | Вставляется тишина либо пропускаются полные кадры; применяется громкость |
| Независимые выходы | Чтение и переполнение одной очереди не меняют другую |
| Дрейф | Имитация более быстрого и медленного устройства удерживает очередь в пределах |
| Декодирование | PCM16/PCM24, моно float и некорректные числовые значения преобразуются ожидаемо |
| Защита маршрута | Источник не выбирается для повторного программного вывода |

## Интерфейс и диагностика

`--ui-smoke <файл.png>` создаёт окно, проверяет размещение важных элементов и отсутствие пересечений кнопок действий, затем сохраняет снимок. Этот режим не запускает передачу и не сохраняет пользовательские настройки. Снимок нужно просмотреть; проверка не охватывает все масштабы DPI, размеры экранов и пользовательские действия.

`--devices <файл.json>` сохраняет активные устройства воспроизведения и их параметры. `--licenses <файл.txt>` извлекает встроенные лицензионные уведомления. Эти команды не меняют системный выход.

Дополнительные аппаратные команды запускаются вручную:

| Команда | Действие |
| --- | --- |
| `--live-test <отчёт.txt> <sourceId> <targetId>` | Воспроизводит тестовый тон на источнике, передаёт копию и ищет этот тон на loopback целевого выхода |
| `--lease-test <отчёт.txt> <sourceId>` | Временно меняет роли Console и Multimedia, возвращает их и проверяет сохранение Communications |
| `--tone <отчёт.txt> <outputId>` | Воспроизводит отдельный тон на указанном устройстве для прослушивания |

Для содержательной проверки переключения `sourceId` должен отличаться от исходного системного выхода. Идентификаторы берутся из отчёта `--devices`, а не из примеров или чужих журналов. Аппаратные команды не являются частью обычного запуска приложения.

## Историческая аппаратная проверка: 22 октября 2026

Исходная версия проверена на Windows 11 x64 с проводными и Bluetooth-наушниками:

- Маршрут от Bluetooth-источника к проводному выходу передал тон 523,25 Гц; тон обнаружен на loopback целевого выхода.
- Во время короткой проверки не зарегистрированы пропуски кадров и опустошения целевой очереди.
- Акустически подтверждено воспроизведение в обеих парах.
- Назначение и восстановление Console / Multimedia проверены отдельно; Communications сохранился.
- Прошли десять детерминированных проверок опубликованного EXE; интерфейс создан и его снимок просмотрен.

Точное акустическое рассогласование не измерялось. Физическое отключение Bluetooth во время передачи отдельно не проверялось. Эти результаты подтверждают проверенный сценарий и не устанавливают совместимость со всеми гарнитурами, драйверами или профилями Bluetooth.
